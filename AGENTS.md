# AGENTS.md

This file provides guidance to agents when working with code in this repository.

Rust 2021 Cargo workspace: `wuffagent-core` (shared lib, crate name `wuffagent_core`) + `wuffagent-egui` (eframe 0.36 GUI binary that depends on core; core also depends on `egui` 0.36 directly for `egui::ImageSource` in the chat state, and the UI uses `egui_plot` 0.37 for the usage chart).

all files have to be UTF-8 encoded and use CRLF! no BOM!

## Commands

- Build: `cargo build` (all) / `cargo build -p wuffagent-core` / `cargo build -p wuffagent-egui`
- Run GUI: `cargo run -p wuffagent-egui`
- Test all: `cargo test` (workspace; the egui crate has a few pure-logic tests too, see below)
- Run a single test: `cargo test -p wuffagent-core <test_name>` (e.g. `cargo test -p wuffagent-core test_trim_conversation`)
- Filter by module: `cargo test -p wuffagent-core client::session`
- **Windows:** if `wuffagent-egui.exe` is running, `cargo build` fails with `failed to remove file ... (os error 5)` when relinking — close the app first.

## Key non-obvious facts

- **No rustfmt/clippy config** — default `cargo fmt` / `cargo clippy` conventions apply; no CI lint gate.
- **Workspace dev profile is optimized** — `[profile.dev] opt-level = 1, debug = "line-tables-only"` in the root `Cargo.toml` because egui re-runs the whole UI closure on every repaint (unoptimized debug is 10–50× slower on drag/scroll/typing). Don't "fix" it back.
- **Tests** are mostly inline `#[cfg(test)] mod tests` in each source file; some modules split tests into a sibling file (`client/tests.rs`, `types/tests.rs`, `agents/config/tests.rs` via `#[cfg(test)] mod tests;`, `config/tests.rs`, `memory/*/tests.rs`; egui side: `ui/agent_history/tests.rs`, `ui/chat_feedback/tests.rs`, `ui/improvements/tests.rs` — pure logic, no window). Async tests use `#[tokio::test]`. `tempfile` is the only dev-dependency and tests use `std::env::temp_dir()` for isolation. MCP integration tests (`tools/mcp/mod.rs`) spawn a small python mock server over stdio and **skip themselves** when no `python`/`python3` interpreter is available.
- **All app data is home-based** (wuffagent-core/src/config/paths.rs): `~/.wuffagent/` holds `config.json`, `sessions/`, `agents/` (+ `agents/history/`), `memories/<project>.json` (default project `default`), `usage.jsonl`, and the one-shot `restart.json` marker. The exception is **plugins**, which load from the *platform* config dir: `dirs::config_dir()/wuffagent/plugins` (e.g. `%APPDATA%\wuffagent\plugins` on Windows). There is no exe-relative/portable config path anymore.
- **Agent discovery order** (wuffagent-egui/src/main.rs + `AgentManager::list_agents`): primary dir `~/.wuffagent/agents/` (sibling of `config.json`), then read-only search dirs `./agents` (cwd) then `<exe dir>/agents`. First-seen name wins dedup; `AgentManager` writes only to the primary dir, never to search dirs. Legacy `WorkerConfig` JSON (and inline `agent_config` in `config.json`) is silently migrated to `AgentConfig` — `personality` → `system_prompt`, `can_invoke` → `handoff_targets`, `task_timeout_ms` 0 → 60000, `restart_enabled: true`.
- **Agent prompt history (F4)** — `AgentManager::edit_agent` snapshots the current `agents/<name>.json` into `agents/history/<name>-<unixts>[-seq].json` before overwriting (and again on revert); at most 20 snapshots per agent are kept. Seq numbering is max+1, never first-free-slot (a reused low seq sorts as oldest and gets pruned).
- **`handoff` and `restart` are per-execution tools** — NOT registered in `register_builtins`; `Agent::new` injects them (and the per-agent `shell`) with their own state (mailboxes, agents dir, allowlist). Their visibility is gated by `handoff_enabled` / `restart_enabled` flags, **not** `allowed_tools` (same as `shell`). There is no `agent_call` tool anymore (only a stale doc comment mentions it) — `handoff` is the agent-to-agent mechanism.
- **Agent-profile self-modification (T1)** — `list_agents` / `edit_agent_profile` ARE shared-registry builtins (`builtin::register_agent_tools` in `wuffagent-egui/src/main.rs`, bound to the same dir set as the UI selector: `~/.wuffagent/agents` + `./agents` + `<exe>/agents`). Visibility is gated by the profile's `allowed_tools` (no `*_enabled` flag). `EditAgentProfileTool` writes IN-PLACE through an `AgentManager` bound to the profile's ACTUAL directory (F3 pattern → F4 snapshot lands next to the profile), canonicalizes oddly-named files to `<name>.json` on edit (`AgentManager::canonicalize_profile_file`), validates names (they become filenames), and requires `allow_self_removal: true` to remove `list_agents`/`edit_agent_profile` from `allowed_tools` (no self-elimination). Edits apply from the NEXT message (the running agent's prompt/tool list were fixed at turn start); the UI selector re-scans every frame, so no refresh event is needed.
- **Plan mode is gone** — the old planner → supervisor → workers pipeline and the `/plan` command were removed. `AgentEngine::execute_with_tools(request, system_prompt, tool_policy, image, cancel)` is the single execution path (chat path): the UI-selected profile supplies the system prompt + tool policy; chat runs with `task_timeout_ms = 0` (no force-kill).
- **MCP** (wuffagent-core/src/tools/mcp/) — hand-rolled JSON-RPC 2.0 (MCP revision 2025-06-18), no SDK; transports are stdio (child process, line-delimited) and Streamable HTTP. `McpManager` owns a **dedicated 2-worker tokio runtime** because all MCP I/O is async and the UI thread lives in the main runtime where `block_on` is not allowed — the sync `*_sync` wrappers must be called from a non-runtime thread. Server tools are mirrored into the shared `ToolRegistry` as `mcp__<server>__<tool>`, so per-agent `ToolManager` rebuilds pick them up (empty `allowed_tools` = all tools; otherwise the full `mcp__...` name must be listed). Config: `mcp_servers` array in `config.json` (`#[serde(default)]`, per-server `enabled` default true, `timeout_secs` default 60); enabled servers auto-connect at startup.
- **Token usage log** (wuffagent-core/src/usage/) — `client` appends one JSONL line per completed LLM call to `~/.wuffagent/usage.jsonl` via `UsageRecorder` (best-effort: serialize/I/O failures are `tracing::warn!`ed once, then `debug!`, and never propagate). `stats` is pure aggregation (tolerant JSONL loading, hour/day/week bucketing with zero-filled windows, incremental reader); all bucket math uses local *wall-clock* `NaiveDateTime`s so DST can't shift boundaries. `client` → `usage` is an allowed dependency direction (`usage` only uses `config`/`types`).
- **Self-restart / auto-resume** — the `restart` tool runs an optional `build_cmd` (600 s timeout, output to a temp log), writes a `RestartRequest` to a per-execution mailbox; `Agent` emits `AppEvent::RestartRequested`; the UI saves the session, writes `~/.wuffagent/restart.json` (`{session_id, reason}`), relaunches the binary, and closes. `main` consumes the marker **once** (read + delete) before the session store is built, sets the active session, and posts a continue turn with the reason.
- **Second dedicated tokio runtime (memory)** — besides the MCP runtime, `main` builds a 2-worker `memory_runtime` for UI-triggered memory maintenance: the UI thread lives inside the `#[tokio::main]` runtime (eframe::run_native blocks there), so the memory panel runs the async maintenance pass on a helper thread that `block_on`s this dedicated runtime — never from the UI thread. Memory LLM calls use a separate `ChatClient` with a 3600 s timeout (`MEMORY_LLM_TIMEOUT_SECS`); the effective give-up point is the per-step `memory_maintenance_timeout_secs`.
- **Images** — egui ships no image decoders: `wuffagent-egui/src/image_loader.rs` registers an `ImageBytesLoader` for `ImageSource::Bytes` (pasted/attached images + chat-bubble images) at startup. Paste goes through `arboard` (clipboard), file pick through `rfd`; the `image` crate (png/jpeg/gif/bmp/webp) decodes files and re-encodes clipboard pixels as PNG. Picked images become `data:` URIs stored on the user `Message.image` and in `SessionRuntime.pending_image`.
- **egui `main.rs` re-exports core modules** (`pub use wuffagent_core::{types, client, config, server, sessions, tools, agents, memory}`) so `wuffagent-egui/src/ui/*` can use `crate::...` paths instead of full `wuffagent_core::` paths. `tracing` filter defaults to `debug,naga=off` (naga/wgpu is extremely chatty) with a custom `FormatEvent` that drops egui-winit's expected "arboard paste error" noise line.
- **Config path resolution**: `get_config_path()` = `~/.wuffagent/config.json`; `Config::save()` writes to `file_path` (set by bootstrap). `sessions_dir(&config_path)` = sibling `sessions/` dir.
- **Agent config migration**: `AgentManager::load_from_dir`/`load_agent_file` and `Config` deserialization both silently migrate legacy `WorkerConfig` / inline `agent_config` JSON to the new `AgentConfig` format (the `Config` path writes `agents/general.json` as a side effect during config load).
- **Plugin tool ABI** (wuffagent-core/src/tools/dynamic/loader.rs): plugins are native libs exporting `wuff_tool_metadata` and `wuff_tool_create` C symbols, loaded via libloading from the platform config dir's `wuffagent/plugins`.
- **Reasoning effort wire mapping** (wuffagent-core/src/types.rs): `ReasoningEffort::High` serializes to `"xhigh"` on the wire, and `Off` is omitted from requests entirely.
- **Session file format**: plain JSON, or base64 text prefixed with `WUFFENC` magic bytes (7 bytes + 12-byte nonce + ChaCha20Poly1305 ciphertext). `load_session` returns `None` for encrypted files — callers must use `decrypt_and_load_session`.
- **Memory file writes are atomic** via temp-file + rename (`wuffagent-core/src/memory/storage.rs`); keep this pattern for any new file persistence.
- **Module dependency rules** documented in wuffagent-core/src/lib.rs: `types` has no internal deps; `llm` depends on `client`+`types`; `client` depends on `usage` (one log line per completed LLM call); `agents` depends on `llm`, `client`, `tools`, `types`, `sessions`, `memory`; `memory` depends on `llm`+`types`; no circular deps between top-level modules. `config_types` mirrors `config` re-exports for backward compatibility — don't delete it.
- **Web-search parser fixtures**: the offline parser tests in `tools/builtin/web_search/tests.rs` load committed snapshots from `wuffagent-core/tests/fixtures/` (`bing.html`, `yahoo.html`, `ddg.html`, `yahoo-live-2026-09.html`) via `include_str!`. The repo-root `test_dir/` is leftover empty directories, not used by tests. Keep fixture files reasonably small; don't commit other large captures.
